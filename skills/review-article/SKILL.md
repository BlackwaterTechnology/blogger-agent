# Review Article Skill

## Overview

本 skill 担任文章草案的**终审官 (Chief Verification Officer / Evaluator)**。基于第一性原理与 **T-A-O 认知协作架构**，它对目标 `article.md` 进行百分制品控审查，彻底扫除 AI 腔陈词滥调、修复排版缺陷、核查真实性与移动端小字截断问题，并直接修改文件。

---

## 质量审核四大维度（百分制打分卡）

审核者必须按照以下 100 分制标准评估并修正草案：

```
                      ┌─────────────────────────────────────────┐
                      │        文章质量百分制打分卡 (100分)       │
                      └────────────────────┬────────────────────┘
                                           │
        ┌──────────────────┬───────────────┴──────────────┬──────────────────┐
        ▼                  ▼                              ▼                  ▼
 【1. 认知与论点】30分   【2. 文本与质感】25分          【3. 视觉与认知密度】25分 【4. 传播与合规】20分
 · 一句话主张 (10)      · 消除说教代词 (8)             · 2-4张高清结构图 (10)    · 标题冲突张力 (8)
 · 2+项硬核证据 (10)    · 开门见山直击痛点 (8)          · 图文紧密显式引用 (8)    · desc 60-120字 (6)
 · 命名实体/货币 (10)   · 剔除 AI 腔与废话 (9)          · 移动端字号≥22px无截断(7)· 0 真实性幻觉 (6)
```

## Workflow

### 阶段 1：发布前自审 (Pre-flight Rubric Audit)

读取目标 `article.md` 文件，对照百分制标准**直接修改文件**修复问题：

```text
【发布前 Pre-flight 检查清单】
1. 极化主张与标题：标题是否具备反直觉张力？若为平铺直叙的话题陈述，必须改写。
2. 社交货币与命名实体：文中是否有明确提炼的方法论或概念实体（如 T-A-O 架构、审核权倒置悖论）？若没有，必须归纳提炼。
3. 人称排查（一票否决）：全局搜索“你/你的/您/您的”。正文叙述中绝不能出现第二人称代词！统一改写为“我们/大家/自身/开发者”或省略。
4. 开篇检查：第一句话能否让人停止滚动？若为“在……快速发展的今天”，必须重写为具体场景或工程痛点开篇。
5. 证据硬度：每个小节是否包含至少 1 处硬核证据（具体代码、真实判例、项目名称、对比数字）？
6. 配图数量与孤儿图：正文必须包含 2~4 张高清结构图表（封面除外）。每张图必须在上下文中被显式引用并解析。
7. 移动端字号与小字重构（CRITICAL）：用 view_file 或 Read 工具检查生成的 PNG 图片。
   - 正文节点/文本字号是否 ≥ 20px - 22px？
   - 图片中是否存在段落/长句堆砌？若有，必须将其极简抽象为 4-8 字短语，并放大字号（或重绘为 SVG 极简卡片）。
   - 是否存在右侧/底部边框截断？若有截断，重绘为 SVG 横向泳道。
8. 摘要长度：`desc` 实际字符数严格落在 60–120 字符范围内。
9. 0 真实性幻觉：核对文中所有 API 参数、法律判例、历史年份与项目名称，确保 100% 真实准确。
```

---

### 阶段 2：AI 腔急救包替换

扫描正文，若发现高危陈词，**写出即重写**：

| ✗ 写出即重写 | ✓ 替换方向 |
|------|------|
| "你 / 你的 / 您 / 您的" (正文叙述中) | 改写为 "我们 / 大家 / 自身 / 开发者"，或直接省略人称 |
| "在……快速演进/蓬勃发展的今天" | 替换为具体的工程痛点、场景或实验数据开篇 |
| "我们不禁要思考" / "值得深思" | 直接抛出具体问题或矛盾冲突 |
| 段落收尾："未来可期 / 拭目以待 / 让我们一同见证" | 直接结束。中文写作不需要总结的总结 |
| 生硬的小标题数字编号（`### 1. 核心背景`） | 改写为自然流畅的结构短语（如 `### 核心背景与工程瓶颈`） |

---

### 阶段 3：格式微调与报告

修改 `article.md` 后，向主叫方报告打分卡得分及修改细节。
