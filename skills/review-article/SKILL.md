# Review Article Skill

## Overview

本 skill 担任文章草案的**终审官 (Chief Verification Officer / Evaluator)**。基于第一性原理与 **T-A-O 认知协作架构**，它对目标 `article.md` 进行百分制品控审查，彻底扫除 AI 腔陈词滥调、修复排版缺陷、核查真实性与移动端小字截断问题，并直接修改文件。

---

## 质量审核四大维度（百分制打分卡）

审核者必须按照以下 100 分制标准评估并修正草案：

```
                      ┌─────────────────────────────────────────┐
                      │        文章质量百分制打分卡 (100分)       │
                      └────────────────────┬────────────────────┘
                                           │
        ┌──────────────────┬───────────────┴──────────────┬──────────────────┐
        ▼                  ▼                              ▼                  ▼
 【1. 认知与论点】30分   【2. 文本与质感】25分          【3. 视觉与认知密度】25分 【4. 传播与合规】20分
 · 一句话主张 (10)      · 消除说教代词 (8)             · 4-6张一鱼两吃自闭环卡片(10)· 标题冲突张力 (8)
 · 2+项硬核证据 (10)    · 开门见山直击痛点 (8)          · 图文紧密显式引用 (8)    · desc 60-120字硬顶(6)
 · 命名实体/货币 (10)   · 剔除 AI 腔与废话 (9)          · 移动端字号≥28px分栏≤2(7)· 0 真实性幻觉 (6)
```

## Workflow

### 阶段 1：发布前自审 (Pre-flight Rubric Audit)

读取目标 `article.md` 文件，对照百分制标准**直接修改文件**修复问题：

```text
【发布前 Pre-flight 检查清单】
1. 极化主张与标题合规：标题是否具备反直觉张力？若为平铺直叙的话题陈述，必须改写。**严格检查标题是否包含 ` ｜ `、` —— `、` - ` 及两侧空格**，若有，一律优化为中文冒号 `：` 或自然标点，且确保前 18~22 字符具有完整认知吸引力。
2. 社交货币与命名实体：文中是否有明确提炼的方法论或概念实体（如 T-A-O 架构、审核权倒置悖论）？若没有，必须归纳提炼。
3. 人称排查（一票否决）：全局搜索“你/你的/您/您的”。正文叙述中绝不能出现第二人称代词！统一改写为“我们/大家/自身/开发者”或省略。
4. 开篇检查：第一句话能否让人停止滚动？若为“在……快速发展的今天”，必须重写为具体场景或工程痛点开篇。
5. 证据硬度：每个小节是否包含至少 1 处硬核证据（具体代码、真实判例、项目名称、对比数字）？
6. 配图数量与“一鱼两吃”自闭环审查 (Dual-Delivery Storyboard Audit - CRITICAL)：
   - 配图数量：全篇必须包含 4~6 张高清卡片（1 张复合封面 + 3~5 张正文核心插图）。
   - 【一鱼两吃自闭环检查】：检查整套插图是否构成完整的 5 幕叙事画册（Hook 封面 ➔ 矛盾对抗 ➔ 机制拓扑 ➔ 落地决策 ➔ 复盘互动）。每张图是否自带独立 Takeaway 结论条？读者脱离正文仅看这套图能否获得 80%~90% 的核心认知？
   - 【模态多样性检查】：检查全篇配图是否过于单一雷同（如全是一模一样的暗蓝框图）。提倡混配【模态 1】具象场景隐喻图与原生 SVG。
   - 孤儿图检查：每张插图必须在上下文中被显式引用并解析。
7. 移动端字号、分栏、自适应比例与安全区审计 (Mobile Readability & Deck Adaptation - CRITICAL 一票否决项)：用 view_file 或 Read 工具检查生成的 PNG 图片与 SVG 源码。
   - 【画布比例】：正文插图是否优先采用了 4:3 (1200x900) 或 3:2 (1200x800) 或纵向流，杜绝 16:9 扁平插图在图片消息竖屏流中产生大面积黑边。
   - 【字号硬底线】：在 1200px 画布中，所有文字字号是否严格 ≥ 28px（核心大标题 ≥ 44px，核心节点 ≥ 32px）？若为 1600px 画布，是否严格 ≥ 36px？若有任何低于 28px 的小字，判定不合格并立即放大重绘！
   - 【分栏防拥挤】：横向分栏是否严格 ≤ 2 栏？严禁横向并排 3 栏或 4 栏卡片！多步骤时序流程必须采用【垂直纵向流转 (Top-to-Bottom)】或【2x2 四象限网格】。
   - 【卡片极简短语化】：单张卡片内文字是否严格在 2~3 行短语内（每行 8~14 字）？若存在整句段落堆砌，必须压缩为短语化关键词，详细逻辑留给正文。
   - 【AI 绘图 0 俗套审查】：若包含 AI 生成插图，检查画面中是否出现了发光蓝脑、机械手握手、科幻 HUD 矩阵或扭曲乱码英文字符。若有，必须按照 5 大杂志社论艺术风格重新生成！
   - 【无截断与清晰度】：是否存在右侧/底部边框截断或节点裁切？若发现 PlantUML 图表有节点截断或质感较平，必须重绘为原生 SVG 矢量图（`sips -s format png --resampleWidth 1920` 渲染）进行替换。
8. 摘要长度与接口安全：`desc` 实际字符数严格落在 60–120 字符范围内（绝对禁止超过 120 字符，防微信后台接口报 64703 错误）。
9. 0 真实性幻觉：核对文中所有 API 参数、法律判例、历史年份与项目名称，确保 100% 真实准确。
10. LaTeX 符号过滤：检查正文中是否存在 `$\rightarrow$`、`$\Leftarrow$` 等行内 LaTeX 数学符号。若有，一律自动替换为原生 Unicode 箭头（`→`、`⇒`），防止微信富文本渲染失真。
11. 微信合集校验 (collection)：必须包含在 `blogger.toml` 的 `article_collections` 列表中。若不在列表中，必须修正为有效合集。
12. 封面架构与居中安全区审查 (Editorial Cover & Safe Zone Audit - CRITICAL)：用 view_file 查看 cover.png 图像。
    - 检查 1：是否平铺了正文 20+ 字的全长技术标题？若有，必须解耦为 4-8 字爆破 Hook 短语。
    - 检查 2：是否具备【双栏复合杂志架构】（左侧爆破 Hook + 右侧高对比度微型信息图/数据对比卡片）？
    - 检查 3：核心 Hook 与右侧卡片是否收敛在中央 60% 安全区，防止一键转为图片消息（3:4 / 1:1 裁剪）时切字。
    - 检查 4：严禁使用 3D 霓虹/发光脑/科幻 HUD/满屏假字等 AI 俗套元素。
    - 若未满足双栏复合架构或为单调全长标题，必须立即编写 SVG 复合卡片脚本并重新渲染后替换。
13. 列表空行与断行检查 (List Blank Line Audit)：检查无序列表 (`*`, `-`) 与有序列表 (`1.`, `2.`) 上方是否包含空行。若列表紧贴上文段落，必须插入空行。
```

### 阶段 2：AI 腔急救包替换

扫描正文，若发现高危陈词，**写出即重写**：

| ✗ 写出即重写 | ✓ 替换方向 |
|------|------|
| "你 / 你的 / 您 / 您的" (正文叙述中) | 改写为 "我们 / 大家 / 自身 / 开发者"，或直接省略人称 |
| "在……快速演进/蓬勃发展的今天" | 替换为具体的工程痛点、场景或实验数据开篇 |
| "我们不禁要思考" / "值得深思" | 直接抛出具体问题或矛盾冲突 |
| 段落收尾："未来可期 / 拭目以待 / 让我们一同见证" | 直接结束。中文写作不需要总结的总结 |
| 生硬的小标题数字编号（`### 1. 核心背景`） | 改写为自然流畅的结构短语（如 `### 核心背景与工程瓶颈`） |

---

### 阶段 3：格式微调与报告

修改 `article.md` 后，向主叫方报告打分卡得分及修改细节。
